# 设计说明

系统按一条直线组织：行情进入 `MarketHub`，持仓记在 `PositionBook`，`RiskSystem` 用同一把锁完成委托检查、三级风控和日终清算。

若你不熟悉期货清算，先看下面的术语表，再读 `src/cta_risk/models.py` 顶部的模块说明。

## 术语表

| 术语 | 本项目含义 | 代码里常见名字 |
| --- | --- | --- |
| 乘数 | 一手合约对应的价格单位倍数。盈亏 = 价差 × 手数 × 乘数 | `InstrumentSpec.multiplier` |
| 开仓 / 平仓 | 新建仓位 / 减少仓位。卖出平多、买入平空 | `Offset.OPEN` / `CLOSE` |
| 多头 / 空头 | 做多盼涨；做空盼跌 | `PositionSide.LONG` / `SHORT` |
| 昨结算 | 上一交易日官方结算价，昨仓当日盈亏的起点 | `PriorPosition.prev_settle`（昨仓） |
| 结算价 | 今日收盘后用来盯市的官方价；演示里可用最新价代替 | `settle()` 的 `prices` |
| 盯市基准 | 算当日盈亏时减掉的那个价。今仓=开仓价，昨仓=昨结算 | `OpenLot.mtm_basis` |
| 盯市盈亏 | `(现价 − 基准) × 手数 × 乘数 × 方向` | `mtm_pnl()` |
| 平仓盯市 | 今日已平仓实现的盯市盈亏合计 | `AccountState.realized_pnl`、日报 `close_pnl` |
| 持仓盯市 / 浮盈 | 未平仓相对基准、按最新价或结算价算出的盈亏 | `PositionBook.floating`、日报 `position_pnl` |
| 权益 | 账户净值 ≈ 上日权益 + 平仓盯市 + 持仓盯市 − 手续费 | `Metrics.equity` |
| 保证金 | 持仓占用的资金；可用 = 权益 − 保证金 | `Metrics.margin` / `available` |
| 名义敞口 | 仓位规模 = 价格 × 手数 × 乘数（不是盈亏） | `notional` |
| 逐日盯市 | 日终用结算价重估持仓，盈亏计入权益，基准改写为今日结算价 | `RiskSystem.settle` |
| 熔断 | 当日盯市亏损触线后禁止开仓，需人工恢复 | `AccountState.halted` |

手算一眼能对上的例子（螺纹乘数 10）：多头昨结算 3000、现价 3050、10 手 → 浮盈 5000 元。

## 行情

最新价来自两个公开网页，不需要柜台账号：新浪财经 `hq.sinajs.cn`，东方财富 `futsseapi.eastmoney.com`。页面上的「拉取真实行情」对配置里的合约各拉一次。2026-10-19 仍在交易的是螺纹 `rb2701`、铁矿 `i2701`、沪深 `IF2612`、中证 `IC2612`。交易所和合约代码都是本项目自己选的。

昨结算写在 `config/system.yaml`，开盘前最新价先放在昨结算上。拉到的价格进入同一个 `MarketHub`。网页行情没有交易所逐笔序号，序号按每个源自己的拉取次数递增。同一个交易所时间戳只采用先到的那一笔，所以两个网站报同一个价不会熔断两次。

断线后补回中间丢失的逐笔，网页接口给不出来。这条规则用演示序列验证：序号跳号时先缓存，缺号到齐后按顺序放行；时间早于当前最新价的回补只留档。风控只在价格真正变化时重算一次。

## 持仓

一个账户可以同时持有多头和空头，账户之间不共享盈亏。平仓按开仓日先开先平：卖出平多，买入平空。平仓数量超过持仓时整笔拒绝。

今仓的盯市基准是开仓价，昨仓的基准是昨结算价。查询可以按账户，也可以按合约。

## 三级风控动作

当日盯市盈亏 = 今日已平仓盈亏 + 持仓浮盈。手续费从权益里扣，不放进亏损告警/熔断口径。

多头盈亏是 `(价格 - 基准) × 手数 × 乘数`，空头相反。最大回撤相对账户高水位权益计算。

| 维度 | 指标 | 告警 | 限制下单 | 熔断 |
| --- | --- | --- | --- | --- |
| 资金 | 当日盯市亏损 / 初始资金 | ≥ 2% | — | ≥ 3% |
| 资金 | 最大回撤 / 高水位 | ≥ 5% | ≥ 10% 禁开仓 | — |
| 持仓 | 单品种名义敞口 / 总敞口（≥2 品种） | ≥ 50% | ≥ 70% 禁加该品种 | — |
| 持仓 | 单品种名义本金 / 权益 | — | ≥ 3 倍禁加该品种 | — |

规则按 `(账户, 规则, 合约)` 去重：越过阈值发一条事件，回落后发恢复事件。**熔断例外**：价格涨回去也不会自动解除，需要人工恢复；恢复时如果亏损还在，会立刻再次熔断。平仓始终允许。

阈值写在 `config/system.yaml`。拒单、风控事件和清算完成写入 `cta_risk.*` 日志。

## 回测

`cta_risk.backtest.run_backtest` 用同一套引擎按时间回放行情和委托（同刻先 tick 后 order），返回权益曲线、委托结果和风控事件。`pixi run backtest` 演示 Gamma 螺纹阴跌：2% 告警 → 3% 熔断 → 开仓拒绝。

## 逐日盯市

```
结算权益 = 上日权益 + 平仓盯市盈亏 + 持仓盯市盈亏 - 手续费
保证金 = Σ 结算价 × 手数 × 乘数 × 保证金率
```

结算后，留仓基准改为今日结算价，当日盈亏从零重新计算。交易日按日历日推进，不跳过周末。

一组可以手算的数字（螺纹乘数 10，保证金率 10%，每手手续费 2 元）：

1. 100 万开多 10 手，价 3000，结算 3050。持仓盯市 5000，手续费 20，权益 1,004,980。
2. 次日平 4 手，价 3100，剩余 6 手结算 3080。平仓盯市 2000，持仓盯市 1800，手续费 8，权益 1,008,772。

空头开在 3000、结算 2900 时，2 手盈利 2000。
